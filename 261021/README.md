# 自転車の需要予測を支えるMLOps基盤

自転車が1時間に何台利用されるかを予測し、学習からモデルの保存、予測の提供、監視、復旧までを試す学習用ソフトウェアです。
MLOps（Machine Learning Operations）は、このように機械学習モデルを継続して運用するための仕組みを指します。

最初の実験にはUCI（University of California, Irvine）の公開データ集を使い、別の予測対象としてCapital Bikeshareの利用履歴も評価しました。

公開されている過去のデータで運用を再現しています。現在の需要を予測する公開サービスや、実店舗の売上改善を実証した製品ではありません。

## 何ができるか

```mermaid
flowchart LR
    data[実績データ] --> check[監査・学習・精度評価]
    check --> registry[モデル登録]
    registry --> api[予測・記録・監視]
    api --> decision[人が配信可否を判断]
```

予測の提供にはAPI（Application Programming Interface）を使います。これは、別のプログラムから決められた形式で予測を要求できる窓口です。
MLflowは学習結果とモデルの管理、PostgreSQLは観測値・予測・操作履歴の保存、FastAPIは予測要求の受付を担当します。
モデルを切り替えるときは、CaddyというWebサーバーが接続先をBlueまたはGreenへ切り替えます。BlueとGreenは、新旧モデルを別々に動かす2つの枠の名前です。

同じ要求を送り直すと、保存済みの予測と当時のモデル番号を返します。
予測の保存に失敗した場合や、配信の条件を満たさない場合は成功として扱いません。

## 現在の結果

2026年11月16日に今回の作業範囲を完了しました。実装の完成と、候補モデルの配信可否は別々に判断しています。

| 対象 | 結果 | 読み取れること |
|---|---|---|
| 製品の実装と試験 | ローカルの単体テスト667件、実装コミットの自動試験、保存結果の再計算、試験環境の後片付けを確認 | 試験した条件の範囲で機能が動作した |
| Capital候補の予測精度 | 検証期間・最終評価期間とも合格 | 固定した過去データ上で比較用の予測方法を上回った |
| 同候補の運用試験 | 応答時間などの数値条件は達成したが、記録時刻の逆行があり受入不可 | 配信判断に使える運用証拠が不足している |
| 同候補の最終判断 | **配信不採用**。登録情報の配信許可は`blocked`のまま | 精度合格だけを理由に配信しない |
| 時計の調査 | 未解決のまま保留し、今回の作業範囲から除外 | 時計の正確さを保証した結果ではない |

自動試験にはCI（Continuous Integration：変更のたびに試験する仕組み）を使っています。
過去の未達試験を合格に書き換えてはいません。不採用になった候補の追加採用試験は中止しました。
詳しい判断根拠は文書一覧の「Capitalの評価と判断」を参照してください。

### 精度と応答時間の違い

精度は「予測が何台ずれたか」、応答時間は「予測が返るまで何秒かかったか」です。
MAE（Mean Absolute Error：平均絶対誤差）は、予測と正解の差を絶対値にして平均したものです。
RMSE（Root Mean Squared Error：二乗平均平方根誤差）は、大きく外した予測の影響を強く受ける指標です。
Capital候補の精度は次のとおりです。予測対象は1時間あたりの利用開始件数で、値は小さいほど良い結果です。

| 評価期間 | 件数 | 候補のMAE | 比較基準のMAE | 候補のRMSE | 比較基準のRMSE |
|---|---:|---:|---:|---:|---:|
| 検証：2026年6〜7月 | 1,464 | 137.392476 | 237.549095 | 226.003415 | 361.975333 |
| 最終評価：2026年8月1日03時〜10月1日00時未満 | 1,461 | 143.693098 | 247.608899 | 228.689254 | 371.052215 |

比較基準は前日同時刻の実績を基本とし、利用できない場合は学習データの曜日・時刻別平均、さらに全体平均を使う簡単な予測方法です。
合格条件は各期間で「候補のMAEが比較基準より小さい」「候補のRMSEが比較基準以下」の両方です。

運用試験では準備用の50要求を除く1,000要求を順番に送り、エラー0件、p95約84.05ミリ秒を記録しました。
p95は応答時間を小さい順に並べたときの95パーセンタイルです。
この試行にはUTC（Coordinated Universal Time：協定世界時）で記録した時刻の逆行が2件あり、運用の合格証拠には使いません。
数値は当該PCでの観測値であり、本番サービスの性能保証ではありません。

## ローカルで始める

Python 3.12と、依存ライブラリを取得できるネットワーク接続が必要です。
以下はリポジトリのルートから実行する、開発環境の準備とデータ確認の手順です。
既存環境を利用する場合は、先に操作手順で保存先と使用中のサービスを確認してください。

```bash
cd 261021
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install --no-deps --no-build-isolation -e '.[dev]'
mlops-bikectl data download
mlops-bikectl data audit
python -m unittest discover -s tests -v
```

`mlops-bikectl`はCLI（Command Line Interface：文字のコマンドで操作する窓口）です。
`requirements.lock`は動作確認したライブラリのバージョンを固定するファイル、`.venv`はこのプロジェクト専用のPython環境です。
WindowsからLinuxを使うWSL（Windows Subsystem for Linux）やDockerの設定、複数サービスの起動方法は操作手順にまとめています。

結果を見るだけなら再学習は不要です。学習や最終評価の再実行は、使用済み期間の再利用につながるため、上の準備手順には含めていません。

## 結果の確認場所

| 確認する内容 | 保存場所・表示先 |
|---|---|
| 学習条件・予測誤差・モデル番号 | 学習時に出力する報告書と、起動済みのMLflow管理画面 |
| APIの準備状態とモデル番号 | 起動済みサービスの`/ready`と`/version` |
| 警告・試験・CIの公開記録 | `docs/reviews/`の用途別JSONファイル |
| 実行コマンド・失敗・原因の仮説 | `work_log.md` |
| 元データ・データベース・詳細なログ | Git対象外の`data/`。公開リポジトリだけでは全原本は揃わない |

UCI用の標準構成では、MLflowは`http://127.0.0.1:5000`、予測の入口は`http://127.0.0.1:8080`です。
サービスが停止している場合は表示できません。結果確認のために既存サービスを無断で起動・変更する手順ではありません。
Capital用の試験環境とはモデル名・保存先・ポートを分けています。

JSON（JavaScript Object Notation）は、項目名と値を組にして記録する形式です。
公開した80件の検証記録は、[検証記録の索引](docs/reviews/README.md)から旧ファイル名で探せます。
元の文章とSHA-256（Secure Hash Algorithm 256-bit：内容を照合するためのハッシュ値）も保持しています。

## プロジェクト上の制約

- 予測時点で利用できる過去の情報だけを使います。実績が3時間後に利用可能になるという設定は、実験上の仮定です。
- UCIとCapitalは計測対象が違うため、観測値、モデル、保存先を混ぜません。両者の誤差を同じ対象の性能比較として扱いません。
- 使用済みの検証・最終評価期間は新候補の調整や選定に再利用しません。今回のCapital候補は両期間とも使用済みです。
- モデルは登録番号で固定します。条件を満たしても自動では切り替えず、人が理由を記録して判断します。
- 合成データの成功、隔離試験の成功、予測精度の合格を、そのまま実配信の承認には使いません。
- 実値を含む`.env`、認証情報、元データは公開しません。
