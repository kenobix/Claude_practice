# リアルタイム共同編集アプリ

少人数の勉強会で使うテキスト共同編集アプリです。MVPでは一時的な切断中の編集と再接続後の合流、端末内保存とサーバー保存の状態表示、権限変更や文書削除後の同期を扱う予定です。 [2026年10月14日の計画](../261014/plan_collaborative_editor.md)

Phase 0では3つの `Y.Doc` に更新を逆順や重複で配送し、一部の更新を保留してから届けました。結果をもとにMVPの仕様とフェーズごとの受入条件を定めました。 [作業ログ](work_log.md)

Phase 1ではブラウザでのオンライン共同編集、文書ごとの権限、接続中の利用者表示を実装しました。 [Phase 1の受入結果](docs/acceptance.md#phase-1の受入結果)

## Phase 1を起動する

Node.js 22.18.0以降を使います。リポジトリのルートで次を実行します。

```bash
cd 261125/app
npm ci --ignore-scripts
npm run build
npm start
```

1. ターミナルに表示される `http://127.0.0.1:4173` を開きます。アカウントはアキ（`aki`）、レン（`ren`）、ソラ（`sora`）です。各アカウントのパスワードは起動のたびに生成され、ターミナルに表示されます。
2. アキでログインし、「新しい文書」から文書を作成します。「共有設定」でレンを編集者、ソラを閲覧者にします。
3. レンとソラはそれぞれ別のブラウザプロファイルでログインします。「一覧を更新」を選び、作成した文書を開きます。同じプロファイル内のタブはログイン状態を共有します。
4. アキとレンが本文を編集します。3つの画面で本文と受理順番号が一致し、ソラは閲覧できることを確かめます。

文書一覧、本文、権限、セッションはNode.jsのメモリに保持され、サーバーを終了すると消えます。接続が切れると本文が読み取り専用になり、「接続し直す」でサーバー上の現在の本文を読み直せます。

## Phase 1の試験を実行する

`261125/app` で実行します。ブラウザ試験はビルド済みの画面を使い、Chromiumを3つの独立したプロファイルで起動します。

```bash
npm run build
npm test
npx playwright install chromium --only-shell
npm run test:browser
```

## Phase 0の実験を再現する

Node.js 22.22.2とnpm 10.9.7で確認しました。依存の取得にはnpmレジストリへの接続が必要です。

```bash
cd 261125/experiments
npm ci --ignore-scripts
npm test
```

各端末が受け取った更新の順番、保留の前後の本文、Yjsバイナリのバイト数を出力します。
