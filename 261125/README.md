# リアルタイム共同編集アプリ

少人数の勉強会で使うテキスト共同編集アプリです。一時的な切断中も編集でき、再接続後に変更が合流します。端末内保存とサーバー保存の状態を個別に表示します。 [2026年10月14日の計画](../261014/plan_collaborative_editor.md)

Phase 0では3つの `Y.Doc` に更新を逆順や重複で配送し、一部の更新を保留してから届けました。結果をもとにMVPの仕様とフェーズごとの受入条件を定めました。 [作業ログ](work_log.md)

Phase 1でオンライン共同編集、Phase 2でSQLiteとIndexedDBへの保存と切断復帰を実装しました。Phase 3では権限失効や文書削除後の同期を止め、端末に残った下書きを書き出せるようにしました。 [Phase 3の受入結果](docs/acceptance.md#phase-3の受入結果)

Phase 4の結果とMVPの判定は受入記録にまとめています。 [MVPの受入結果](docs/acceptance.md#mvpの総合判定)・[共同編集デモ（3分）](demo/collaboration.mp4)・[再起動デモ（41秒）](demo/restart.mp4)

## アプリを起動する

Node.js 22.18.0以降を使います。試験ではNode.js 22.22.2とnpm 10.9.7を使いました。リポジトリのルートで次を実行します。

```bash
cd 261125/app
npm ci --ignore-scripts
npm run build
npm start
```

1. ターミナルに表示される `http://127.0.0.1:4173` を開きます。アカウントはアキ（`aki`）、レン（`ren`）、ソラ（`sora`）です。各アカウントのパスワードは起動のたびに生成され、ターミナルに表示されます。
2. アキでログインし、「新しい文書」から文書を作成します。「共有設定」でレンを編集者、ソラを閲覧者にします。
3. レンとソラはそれぞれ別のブラウザプロファイルでログインします。「一覧を更新」を選び、作成した文書を開きます。同じプロファイル内のタブはログイン状態を共有します。
4. アキとレンが本文を編集します。3つの画面で本文と受理順番号が一致し、ソラは閲覧できることを確かめます。

文書と権限の保存先は `261125/app/data/collab.sqlite` です。別のファイルを使う場合は起動時に `COLLAB_DATABASE` を指定します。サーバーを再起動したら、ターミナルに表示される新しいパスワードで同じアカウントにログインしてください。

## 切断中の編集と保存状態

一度開いた文書は、接続が切れても所有者と編集者が編集できます。「端末内保存済み」はブラウザに保存できた状態です。「サーバー保存待ち」の編集は「接続し直す」を選ぶと送信します。「サーバー保存済み」は、現在の編集すべてについてサーバーから保存確認が届いた状態です。

保存確認は送信ごとに2.5秒待ち、届かなければ同じ更新を最大2回再送します。最初の送信と2回の再送で確認が届かなければ、画面を「未接続」に切り替えます。下書きは端末に残ります。通信が戻ったら、ページはそのままで「接続し直す」を選んでください。頻度制限が返ったときは、待ってから自動で再送します。 [保存と再送の仕様](docs/phase2-storage.md#端末の保存と再送)

ブラウザを再起動した場合は、同じプロファイルとアカウントで文書を開きます。編集権限が有効で付与版（`grant_revision`）も変わっていなければ、端末内保存済みの未確認更新を送信します。アプリを開くときはサーバーへの接続が必要です。

## 改行と旧版のデータ

本文の改行はLFで保存します。入力や貼り付けに含まれるCRLFと単独CRは、編集画面でLFにそろえます。

- 旧版で保存した文書にCRが残っていると、閲覧権限がある利用者は「保存済みの本文を書き出す」で元の改行を含むテキストを取得できます。内容を確認し、所有者が新しい文書へ貼り付けてから、必要な利用者に権限を設定してください。
- 端末に残る旧版のデータにCRがある場合は、「同期を停止した下書き」から書き出せます。表示される正式本文と照合し、必要な変更を新しい文書に貼り付けてください。差分の復元に正式本文が必要な場合は、付与版（`grant_revision`）が変わる前に同じアカウントで文書を開くと、端末が書き出しに使う状態を取得できます。
- 復元に必要なデータが足りない場合は画面に表示します。一部だけを復元できたファイルには `-partial` が付きます。本文を復元できない場合はファイルを作りません。正式本文がLFの文書で編集を続けたい場合は、残したい下書きをすべて書き出せたことを確かめてからログアウトし、同じアカウントで開き直してください。ログアウトは、そのアカウントの端末内データを破棄します。 [改行の仕様](docs/design.md#改行と旧版データ)

## 権限変更、削除、下書きの書き出し

所有者は「共有設定」で編集者や閲覧者の権限を変更できます。削除するときは「文書を削除」を押し、確認ダイアログを承認します。その文書は一覧から消え、以後は接続できなくなります。

共有設定の変更や文書削除によって同期できなくなった下書きは、「同期を停止した下書き」からテキストとして書き出せます。閲覧権限が残っていれば、再接続すると現在のサーバー本文を表示します。編集権限を再付与された場合は、現在の本文から編集を再開できます。

「ログアウト」を押すと、そのアカウントの端末内データを破棄します。手元に残したい下書きはログアウト前に書き出してください。セッションが期限切れになった場合は、「ログインし直す」から同じアカウントで接続できます。 [権限と復旧の仕様](docs/phase3-access.md)

## 試験を実行する

`261125/app` で次のコマンドを実行してください。サーバー試験は一時DBを使い、停止試験では子プロセスを `SIGKILL` で停止します。ブラウザ試験ではビルド済みの画面を使い、Chromiumを独立したプロファイルで起動します。

```bash
npm run build
npm test
npx playwright install chromium --only-shell
npm run test:browser
```

LinuxでChromiumの実行に必要なシステムライブラリがない場合は、`npx playwright install --with-deps chromium --only-shell` で導入してください。デモ録画、性能計測、OSの日本語IMEの手順は実験記録にあります。 [デモと性能計測](docs/experiments.md)

## バックアップと復元

バックアップには `npm run backup -- SOURCE.sqlite NEW_BACKUP.sqlite` を使います。稼働中のDBから取得でき、既存ファイルの上書きは拒否します。復元は別パスのDBと新しいブラウザプロファイルで確認します。 [操作手順とシステム構成図](docs/operations.md)

## Phase 0の実験を再現する

Node.js 22.22.2とnpm 10.9.7で確認しました。依存の取得にはnpmレジストリへの接続が必要です。

```bash
cd 261125/experiments
npm ci --ignore-scripts
npm test
```

各端末が受け取った更新の順番、保留の前後の本文、Yjsバイナリのバイト数を出力します。
