# Phase 3の権限、削除、同期エラー

## 権限変更と削除

文書の更新、権限変更、削除は単一のNode.jsプロセスで順に処理する。権限の変更時は文書の権限版と対象利用者の付与版（`grant_revision`）を進め、SQLiteに保存する。コミット後にメモリ上の権限を更新し、対象利用者の既存接続を閉じる。再付与でも付与版を進める。サーバーは `UPDATE` ごとに現在のセッションと権限を確認する。付与版が異なる場合は受理記録を検索する前に `GRANT_CHANGED` を返す。有効な付与版を使う閲覧者の更新は `WRITE_FORBIDDEN` で拒否する。

所有者の削除要求を受けると、SQLiteに `deleted` を記録してから接続を閉じ、一覧と同期対象から外す。削除時点の権限と文書IDをDBに残す。削除済みの本文は起動時にロードせず、旧IDに `STATE` や `APPLIED` を返さない。削除前に受理済みのログと受理記録はDBに残す。

| 経路 | 応答 |
| --- | --- |
| `DELETE /api/documents/:id` | 有効な文書の所有者にはHTTP 200と `{"deleted":true}`。ほかの利用者、存在しないID、削除済みIDにはHTTP 403と `ACCESS_DENIED` |
| `GET /api/documents/:id` | 閲覧権限があればロールと `grant_revision`。本文は含めない |
| `GET /api/documents/:id` または `GET /ws/:id` で削除済みIDを指定 | 削除時点で閲覧できた利用者にはHTTP 410。HTTP APIでは `DOCUMENT_DELETED` を返す |
| `GET /api/documents/:id` または `GET /ws/:id` で閲覧権限がないIDや存在しないIDを指定 | どちらもHTTP 403。HTTP APIではどちらも `ACCESS_DENIED` を返す |

WebSocketへの切り替え失敗をブラウザから判定する場合は、HTTP APIで現在の権限を確認する。切断後に別のロールで再接続できる場合は、そのロールに対応した正式な `STATE` を取得する。

## 端末の下書きとログアウト

端末は文書IDと付与版ごとに、IndexedDBに保存した状態と送信待ち更新を管理する。失効、削除、同期を続けられない更新拒否を確認したとき、該当する付与版の状態に停止理由を記録する。その付与版の状態と送信待ち更新は再送や差分生成に使わない。閲覧権限が残る場合は、サーバーから取得した正式本文を表示する。再付与後は新しい付与版で接続し、正式本文から編集を再開する。

「同期を停止した下書き」から、端末に残った本文をUTF-8のテキストファイルとして書き出せる。下書きには、最後に取得した本文と端末に残った変更が含まれる。文書が一覧から消えた場合も、同じアカウントで開けば端末に残った下書きを書き出せる。端末内のデータの一部が欠けて復元できない場合は、復元できた範囲を書き出したことを表示する。

明示的にログアウトすると、接続と端末内の新規書き込みを止め、セッションを無効にする。アカウント別のWeb Locksでキャッシュを開く処理と破棄を順序づける。IndexedDBを開く直前にセッションを確認し、ログアウト時は開始済みのトランザクションが終わってDBの削除が完了するまで、別アカウントで開けないようにする。同じアカウントで開いた他のタブはDB削除の通知を受けて接続とキャッシュを閉じる。期限切れで同じアカウントにログインし直す場合は、現在の付与版を確認して未確認更新を再送する。

## 更新拒否と復帰

| 理由 | サーバーと端末の動作 |
| --- | --- |
| `GRANT_CHANGED`、`ACCESS_DENIED`、`DOCUMENT_DELETED` | 旧版の送信を止め、対象の下書きを隔離する。閲覧できる場合は最新の `STATE` を読み直す |
| `RATE_LIMIT` | 接続と送信待ちを維持し、端末は350 ms待ってから同じ操作IDとバイト列で再送する |
| `MISSING_DEPENDENCY` | 更新を拒否する。再接続で取得した `STATE` と端末データから必要な差分をまとめ、新しいIDで先に送る |
| `LINE_ENDING` | 適用後の可視本文にCRが残る更新を拒否する。端末は該当する付与版の同期を止め、書き出し用に保持する |
| `INVALID_UPDATE`、`MESSAGE_ID_CONFLICT`、`TEXT_LIMIT`、`UPDATE_LIMIT`、`STATE_LIMIT` | 更新を拒否し、端末は該当する付与版の送信を止めて下書きを隔離する |
| `FRAME_LIMIT` | 長さを示す先頭2バイトを含むヘッダーが1,024バイトを超えた場合は理由を送り、コード1009で閉じる。メッセージ全体が8,389,632バイトを超えた場合は、受信処理でコード1009を返す |
| `SESSION_EXPIRED` | 既存接続を閉じる。再ログインするまで新しい接続はHTTP 401 |

Yjs V1の更新を文書のコピーに適用し、構造と削除の依存関係、形式、本文、完全状態を検査する。破損、末尾の余分なバイト、書式付き本文や本文の属性を含む更新は `INVALID_UPDATE` で拒否する。フレーム、受信した更新、適用後の完全状態にはそれぞれ上限を設ける。拒否した更新では正式本文と受理順番号を保持し、DBへ記録せず、`APPLIED` を送らない。 [上限の定義](design.md#上限とエラー)・[Phase 3の受入結果](acceptance.md#phase-3の受入結果)
