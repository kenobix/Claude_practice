# 実行例と受入条件

## 固定例の期待値

[入力例](../examples/)と同じ名前の項目を[期待値JSON](../examples/expected.json)で引く。各項目に、LFを含む標準出力 `stdout`、終了コード `exit_code`、診断 `diagnostic` を記す。成功時の診断は `null` とする。失敗時は標準エラー出力に診断を1件出し、JSONにある診断フィールドを比較する。診断文 `message` は表示されることを確認する。固定例の `.tiny` は診断のバイト範囲を再現できるようにLFでチェックアウトする。

| 入力例 | 期待値の根拠 |
| --- | --- |
| `arithmetic` | 乗算が加算に優先するため最初の式は7、括弧付きは9。左から計算すると `(20 / 3) * 2 = 12`、`(10 - 3) - 2 = 5` となる。負の除算と剰余は `(-3) * 3 + 2 = -7`、`(-3) * (-3) + (-2) = 7`、`2 * (-3) + (-1) = -7` を満たす。 |
| `branch` | 最初の条件は真で `!false` は真。2番目の `if` は `else` を選び `2 != 3` は真。残る分岐と反復の本体は実行されず、最後の `print` が偽を出力する。 |
| `sum_loop` | 反復ごとに `current` を `i` で初期化する。合計は1、3、6、10、15と変わり、`i` が6で停止する。 |
| `shadowing` | 内側の宣言より前は外側の整数を読み書きする。宣言からブロック末尾までは内側の真偽値を使い、ブロックを出ると外側の整数2を参照する。 |
| `lex_character` / `parse_chain` / `parse_eof` | `全` はコメント外の不正な文字。比較の2個目の `<` は余分なトークン。対応する `)` がなければEOFを示す。 |
| `undefined` / `self_reference` / `redeclaration` | 後方の宣言は参照できない。初期化中の変数は外側に同名の変数があっても参照できない。同一スコープの再宣言を初期値の参照より先に報告する。 |
| `type_condition` / `type_dead_branch` / `type_initializer` | 条件には `bool` が必要。実行されない枝も検査する。初期値は宣言型と一致する必要がある。 |
| `zero_division` / `zero_remainder` | 成功済みの `print 7;` の出力を残す。二項式の左辺でゼロ除算が起きたら、右辺の剰余に進まない。単独の剰余でも除数が0なら停止する。 |
| `step_limit` | ASTでは `while` への進入1回、条件と空ブロックの組が49,999回、次の条件1回で100,000ステップになる。次のブロックに入る前に `{` で停止する。VMでは33,333周と次の定数読み込みで100,000命令になり、次の条件分岐の `while` で停止する。 [命令数の期待値](bytecode.md#命令数の期待値) |

## 境界入力

固定ファイルのほかに、次の手順で境界入力を作る。以下の繰り返しやべき乗の表記は入力データを作るための手順を表す。生成したソースは[言語仕様](language_spec.md)に従う。

| 対象 | 入力の作り方と期待値 |
| --- | --- |
| UTF-8とCRLF | `lex_character.tiny` のLFをCRLFに替えると `E_LEX/lex` の行と列は2と8、範囲は `[21, 24]`。先頭行を `//` とCRLFにし、続けてバイト `0xFF` を置くと `E_INPUT/input`、行2、列1、範囲 `[4, 5]`。存在しないファイルを指定すると `E_INPUT/input` で位置なし。 |
| 字句の最長一致とEOF | `let if1: int = 4; print if1 / 2 <= 3;//終端` を末尾に改行なしで入力する。`if1` は識別子、`/` と `<=` はそれぞれ1トークン、末尾はコメントとEOF。実行結果は `true\n`。空のソースは成功して出力しない。 |
| 段階の優先順 | `print ; @` は `@` で `E_LEX/lex`。 `let x: int = true; print y;` は `y` で `E_UNDEFINED/resolve`。 `let x: int = 0; x = false;` は代入先の `x` で `E_TYPE/type`。いずれも標準出力は空。 |
| ソースサイズ | ASCIIスペースを65,535、65,536、65,537個用意する。最初の2件は空プログラムとして成功し、最後は `E_LIMIT/input` で位置なし。 |
| トークン数 | `{}` を4,095、4,096、4,097個連結する。最初の2件は成功し、最後は8,193個目のトークンである `{` を `E_LIMIT/lex` とする。行1、列8,193、範囲 `[8192, 8193]`。 |
| 構文の深さ | `print` の式に `1` を括弧で63、64、65重に囲む。最初の2件は `1\n` を出力し、最後は65個目の `(` で `E_LIMIT/parse`。別に `print` の式で `1` を `+` で62、63、64、65個つなぐ。62個と63個は成功、64個は `print`、65個は最後の `+` で `E_LIMIT/parse`。 |
| 整数リテラル | `2^4095 - 1`、`2^4096 - 1`、`2^4096` の10進表記を `print` の式に置く。最初の2件は値を出力し、最後はリテラル全体で `E_LIMIT/lex`。超過するリテラルを偽の枝に置いても同じ。別に `1` の前にゼロを5,000個付けたリテラルは `1\n` を出力する。 |
| 整数演算 | `2^4096 - 2` と `2^4096 - 1` の10進表記を、それぞれ `1` と加算して出力する。前者は最大値 `2^4096 - 1` を出力する。後者は `+` で `E_LIMIT/runtime` となり、前に `print 1;` があれば `1\n` を残す。超過する加算を偽の枝に置く場合は成功する。 |
| 出力行数 | `let i: int = 0; while (i < N) { print i; i = i + 1; }` の `N` を1023、1024、1025にする。最初の2件は指定行数で成功し、最後は0～1023の出力を残して `print` で `E_LIMIT/runtime`。出力上限に達した後も、次の `print` の式がゼロ除算なら `E_ZERO_DIVISION` が先になる。 |
| 実行ステップ | `step_limit.tiny` で各処理系が100,000ステップを実行し、次の処理を始めず停止する。ASTの境界を確認するには `let i: int = 0; while (i < 12499) { i = i + 1; }` の後ろに `{}` を1、2、3個付ける。末尾のブロックを除くステップ数は `6 + 8 × 12499 = 99998`。最初の2件は成功し、最後は3個目の `{` で `E_LIMIT/runtime`。VMの境界入力はPhase 3で命令列を基に作る。100,000命令で終わる入力は成功し、100,001命令目を要する入力はその命令を実行する前に停止する。 |

## 段階ごとの受入条件

| 段階 | 必須条件 | 確認方法 |
| --- | --- | --- |
| Phase 0 | 文法、評価順、スコープ、型、上限、最初の診断、処理系の構成が決まっている。固定例と境界入力の期待値を仕様から導ける。 | 元計画と仕様の照合、固定例の出力と診断位置の確認、境界入力の計算、文書と相対リンクの点検。 |
| Phase 1 | `--tokens` と `--ast` で位置付きのトークンとASTを表示できる。入力・字句・構文の失敗は該当のコード、段階、位置、終了コード2となる。 | 最長一致、空入力、LF/CRLF、EOF、資源上限を確認する。優先順位を `(1 + (2 * 3))`、左結合を `((10 - 3) - 2)` の木で確認する。 |
| Phase 2 | AST評価で全固定例と境界例が期待値を満たす。実行前エラーの出力は空で、実行時エラーでは成功済み出力が残る。 | `run --engine ast` と独立期待値を照合する。実行ステップはASTの数え方で確認する。 |
| Phase 3 | VMでも同じ言語仕様を満たし、逆アセンブルとトレースでソース位置を追える。命令列の不具合を検査できる。 | `run --engine vm` を期待値と照合する。不正命令、範囲外ジャンプ、スタック不足、分岐合流の深さの不一致は `E_INTERNAL` と終了コード4を確認する。 |
| Phase 4 | 手書き例と有界の生成プログラムで未説明の不一致がなく、クリーンな環境で再現できる。READMEに再現手順と既知の制約をまとめ、3分のデモを用意する。 | 標準出力、終了コード、診断コード・段階・位置を比較する。実行ステップ上限は処理系ごとの規則で確認する。出力を伴わない計算例も使い、解析・型検査・コンパイル・実行を分けて計測する。Pythonの版、CPU、入力、繰り返し回数、中央値を記録する。 |

Phase 0の確認範囲は文書と期待値までとする。MVPの性能値は測定結果として記録し、VMの速度がAST評価を上回ることは受入条件に含めない。

### ASTとVMで共有する規則

Phase 3のVMでも共通の字句・構文解析、名前解決、型検査を使い、宣言IDを変数スロットに対応させる。宣言を実行するたびに式を評価し、成功すれば初期値を書き込む。両処理系で値の型タグ、二項演算の左辺・右辺・演算の順、整数の範囲と除算・剰余の規則、出力の表記と行数上限を共有する。

実行ステップ上限に達しない場合は、標準出力、最初の診断のコード・段階・位置、終了コードを共通の期待値で照合する。ステップ上限に達する場合は、停止までの出力と診断位置を各処理系の規則に従って確認する。 [言語仕様](language_spec.md)・[演算](../tiny_language/operators.py)・[値](../tiny_language/values.py)

VMの命令列、処理系間の一致、性能は未検証。ローカルの動作確認はLinux x86_64のCPython 3.12.3で行った。
