# バイトコード命令仕様

コンパイラは名前解決と型検査を終えたASTから、メモリ内の命令列とスロットの型一覧を作る。VMは検査済みの命令列を、命令番号0、空のスタック、全スロットが未初期化の状態から実行する。命令番号とスロット番号は0始まりとする。 [言語仕様](language_spec.md)

## 命令とソース位置

スタック効果は取り出す値の個数と積む値の個数を示す。条件分岐はどちらに進む場合も条件値を取り出す。二項演算にはスタックの一番上を右辺、その下を左辺として渡す。

| 命令 | オペランド | 取り出す → 積む | 動作 | 元ソースの位置 |
| --- | --- | --- | --- | --- |
| `PUSH` | 型付きの定数 | 0 → 1 | 定数を積む | リテラル |
| `LOAD` | スロット番号 | 0 → 1 | スロットの値を積む | 参照箇所の識別子 |
| `STORE` | スロット番号 | 1 → 0 | 値を取り出してスロットに格納する | 宣言名または代入先の識別子 |
| `UNARY` | `-`、`!` | 1 → 1 | 単項演算の結果を積む | 演算子 |
| `BINARY` | `+`、`-`、`*`、`/`、`%`、`<`、`<=`、`>`、`>=`、`==`、`!=` | 2 → 1 | 二項演算の結果を積む | 演算子 |
| `JUMP_IF_FALSE` | 飛び先の命令番号 | 1 → 0 | 条件が偽なら指定の命令、真なら次の命令に進む | `if` または `while` |
| `JUMP` | 飛び先の命令番号 | 0 → 0 | 指定の命令に進む | `if` または `while` |
| `PRINT` | なし | 1 → 0 | 値を取り出し、出力上限を確認してLF付きで書く | `print` |
| `HALT` | なし | 0 → 0 | 空のスタックで終了する | EOFの空範囲 |

分岐、ジャンプ、停止以外の命令は次の命令に進む。すべての命令が元ソースの行・列とUTF-8バイト範囲を保持する。

## 命令の生成

式は値を一つ積み、文は完了時にスタックの深さを元に戻す。二項式は左辺、右辺、`BINARY` の順で命令を生成する。ブロックには中の文の命令をソース順に並べる。空ブロックと式のグループ化に対応する専用命令はない。

変数のスロット番号には宣言IDを使う。宣言と代入は、右辺の命令に続けて `STORE` を置く。ブロック内の宣言は通過するたびに初期値を格納する。スロットは実行終了まで保持し、スコープ外からの参照は名前解決で防ぐ。

- `if` は条件式の命令に `JUMP_IF_FALSE` を続ける。`else` があれば、偽の飛び先を `else` 側の先頭にし、真の枝の末尾に合流先への `JUMP` を置く。`else` がなければ、偽の飛び先を `if` 全体の直後にする。
- `while` は条件式の命令に `JUMP_IF_FALSE` を続け、偽の飛び先をループ直後にする。本体の末尾に条件式の先頭へ戻る `JUMP` を置く。
- プログラム末尾に `HALT` を一つ置く。空の枝の先頭や最後の文の直後を指すジャンプも、実在する命令番号を指す。

## 検査とエラー

実行と逆アセンブルの前に、すべての命令の命令名、オペランドの型と範囲、ソース位置を検査する。定数とスロットは `int` と `bool` を区別する。整数定数は4,096ビット以内とする。ジャンプ先は命令列内にあり、停止命令は末尾の1個に限る。

命令列検査は `HALT` のバイト範囲が空（`start == end`）であることを確認する。元ソースのEOFとの対応はコンパイラが受け持ち、字句解析で得たEOFトークンの位置を `HALT` に付ける。

命令番号0から深さ0で始め、各命令のスタック効果を後続の命令へ伝える。条件分岐では両方の経路をたどる。スタック不足、合流点での深さの不一致、停止時の非空スタック、終端を越える遷移、入口から到達できない命令を検出したら実行に進まない。実行中も、演算・条件分岐・格納で値の型が合わない場合や、未初期化のスロットを読んだ場合に内部エラーを返す。処理系の不具合は `E_INTERNAL/internal`、終了コード4とし、特定できる場合は原因となる命令の位置を示す。

演算と出力にはAST評価器と同じ規則を使う。ゼロ除算とゼロ剰余、整数値4,096ビットの超過は演算子の位置で報告する。1,024行を出力した後に `PRINT` を実行しようとしたときは、その位置で停止する。100,000命令を実行した後に次の命令が必要になった場合は、実行前にその命令の位置で `E_LIMIT/runtime` を報告する。停止命令も1命令と数え、100,000命令目の `HALT` は成功する。実行時エラーでは成功済みの標準出力を保持する。

## 逆アセンブルとトレース

`--disassemble PATH` は命令列を検査し、命令を実行せずJSON配列を標準出力に表示する。各要素に `pc`、`op`、`operand`、`line`、`column`、`span` を載せる。定数は `type` と `value` の組とし、整数値は10進文字列、真偽値はJSONの真偽値とする。オペランドのない命令では `operand` は `null` になる。

`run --engine vm --trace PATH` は、実行に成功した命令ごとにJSONを1行、標準エラー出力に書く。逆アセンブルと同じフィールドに加え、1始まりの `step`、次の命令番号 `next_pc`、実行後の `stack`（底から順に並んだ型付きの値）、`store`（その命令が書いたスロット番号と型付きの値）を載せる。`HALT` の `next_pc` と、スロットを書かない命令の `store` は `null` になる。失敗した命令にはトレース行がなく、診断を標準エラー出力に書く。プログラムの `print` は標準出力に書く。

## 命令数の期待値

`while (true) {}` は `true` の `PUSH`、`JUMP_IF_FALSE`、条件へ戻る `JUMP` の3命令を繰り返す。`step_limit.tiny` では33,333周で99,999命令に達し、次の `PUSH` が100,000命令目になる。100,001命令目の条件分岐は実行されず、`while` の位置（行1、列1、範囲 `[0, 5]`）で停止する。

`let i: int = 0; while (i < 11110) { i = i + 1; }` は初期化2命令、反復ごとに条件と分岐4命令、代入4命令、後方ジャンプ1命令を実行する。最後の偽の条件と分岐に4命令かかるため、停止直前までに `2 + 9 × 11110 + 4 = 99996` 命令を実行する。

| ループの直後に加える文 | `HALT` までに必要な命令数 | 期待する結果 |
| --- | ---: | --- |
| `print 7;` | 99,999 | `7` を出力して成功 |
| `print -7;` | 100,000 | `-7` を出力して成功 |
| `print 7 + 0;` | 100,001 | `7` を出力し、EOFで停止 |
| `print 7; print -8;` | 100,002 | `7` を出力し、2個目の `PRINT` の手前で停止 |

同じループに `print 7; print 9 / 0;` を続けると、100,000命令目は `0` の `PUSH` になる。`/` は100,001命令目にあたるため、除算の前に `E_LIMIT/runtime` で停止して `7` の出力を残す。
