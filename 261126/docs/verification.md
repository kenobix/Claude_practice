# Phase 4の一致性検証

## 生成規則と結果

Python 3.12の `random.Random` にseed `261126` を渡し、次の60件を生成した。検査対象は、少数の固定した文の組み合わせと、符号や反復回数を変えたときの実行結果である。 [生成と検証のスクリプト](../tools/compare.py)・[実行結果](../results/comparison.json)

| 系列 | 件数 | 生成条件と独立期待値 |
| --- | ---: | --- |
| `scope-loop` | 24 | 0〜6回のループで、加減乗算、単項の負号と否定、比較、等値、二重のブロック、分岐を組み合わせる。内側の `x` を宣言する前に外側の `x` を更新する。反復番号を `i` とすると内側の初期値は `bias - i × scale`、外側の最終値は `initial + count × bias`。内側で選んだ枝の出力と、代入後の値も照合する。 |
| `divmod` | 20 | 被除数 `-13, -6, 0, 6, 13`、除数 `-4, -3, 3, 4` の全組み合わせを並べ替える。商は有理数を床関数で丸め、剰余は `a - q × b` として求める。商・剰余に加え、`a == q * b + r` と、剰余がゼロかどうかを言語内で出力する。 |
| `zero-divisor` | 16 | ゼロを含む除算・剰余を4通りの式に置き、式ごとに `-9` から `9` の範囲で異なる値を4個選ぶ。左辺で先に失敗する場合と、右辺の失敗で外側の演算へ進まない場合を含む。先行出力を保持し、式の並びから求めた最初の演算子で `E_ZERO_DIVISION/runtime`、終了コード3とする。UTF-8コメントとCRLFを含む元バイト列で位置を照合する。 |

結果は正常44件、実行時エラー16件のすべてが一致した。各入力を両CLIで実行し、LFを含む標準出力、終了コード、診断コード・段階・行・列・バイト範囲を相互に比較し、処理系ごとに独立期待値とも照合した。診断の文言は人向けのため比較から外す。どちらかの実行結果が違えば、両処理系が同じ値を返していても失敗とする。 [自動テスト](../tests/test_phase4.py)

生成した入力は最大6回の反復と小さい整数に限る。この範囲ではステップ上限に届かず、生成テストの `E_LIMIT` は不一致として扱う。正常・異常いずれも、固定例と境界試験を別に実行した。

## 固定例と境界の期待値

- Phase 0の正常4件・異常12件は固定期待値を利用する。無限ループでは標準出力と終了コードを共通の期待値に照合し、診断位置をASTとVMそれぞれの規則から求める。 [固定期待値](../examples/expected.json)・[命令数の手計算](bytecode.md#命令数の期待値)
- ソースサイズ、トークン数、ASTと入れ子の深さ、整数値、出力行数は直前、上限、超過の値を用意する。ASTとVMのステップ境界にはノード進入数と命令数から求めた入力を使う。VMでは100,000命令目の `HALT` が成功し、100,001命令目を実行せず、その命令の位置で止まることを確認する。 [境界入力](acceptance.md#境界入力)
- 実行時の複数エラーは、左辺、右辺、演算の順と、式の失敗を出力上限より先に返す規則に従って検査する。CLI出力から期待値を書き戻す処理は使用しない。

## 再現と不一致の調査

`261126/` で次のコマンドを実行する。ケースIDとseedが分かれば同じ入力を単独で実行できる。

```bash
python3 -B -m tools.compare --seed 261126
python3 -B -m tools.compare --seed 261126 --case zero-divisor-00 --failure-dir /tmp/tiny-language-review
```

不一致があるとスクリプトは終了コード1を返し、`--failure-dir` に元の `.tiny` と両処理系の結果・独立期待値を含むJSONを保存する。実際の不一致が起きた場合は、同じ診断や出力差が残る範囲で文や式を削り、最小化した入力と仕様に基づく原因を記録する。今回の実行で未説明の不一致は0件だった。
