# 言語仕様

## 対象

値の型は `int` と `bool` とする。文は変数宣言、代入、出力、ブロック、分岐、反復とする。関数、配列、文字列、ファイルやネットワークへの入出力は拡張候補とする。

## ソースとトークン

- ソースはUTF-8で読み、LFとCRLFを改行として扱う。空白として読み飛ばす文字はASCIIスペース、水平タブ、改行とする。単独のCRとBOMはコメント外では不正な文字とする。
- `//` はコメントの開始を表す。コメント内のUTF-8文字を次のLF、CRLF、またはEOFまで読み飛ばす。単独のCRはコメントを終わらせない。
- 識別子は `[A-Za-z_][A-Za-z0-9_]*` とし、識別子全体が `let`、`int`、`bool`、`print`、`if`、`else`、`while`、`true`、`false` のいずれかに一致すれば予約語とする。大文字と小文字は区別する。
- 整数リテラルは `[0-9]+` とする。先頭にゼロがあっても10進数とする。負号は単項演算子として読む。
- 構文記号と演算子は下の文法に従い、最長一致で読む。`//` は除算の `/` より先に判定する。数字列の直後に識別子が続く場合は別々のトークンに分ける。

## 文法

`{ X }` は0回以上の繰り返し、`[ X ]` は省略可能な要素を表す。`EOF` は入力の終端を表す。

```ebnf
program     = { declaration }, EOF ;
declaration = "let", IDENT, ":", type, "=", expression, ";" | statement ;
type        = "int" | "bool" ;
statement   = IDENT, "=", expression, ";"
            | "print", expression, ";" | block
            | "if", "(", expression, ")", block, [ "else", block ]
            | "while", "(", expression, ")", block ;
block       = "{", { declaration }, "}" ;
expression  = equality ;
equality    = comparison, [ ( "==" | "!=" ), comparison ] ;
comparison  = term, [ ( "<" | "<=" | ">" | ">=" ), term ] ;
term        = factor, { ( "+" | "-" ), factor } ;
factor      = unary, { ( "*" | "/" | "%" ), unary } ;
unary       = ( "!" | "-" ), unary | primary ;
primary     = INTEGER | "true" | "false" | IDENT | "(", expression, ")" ;
```

加減算と乗除剰余は、それぞれの優先順位内で左結合とする。単項演算子が続く場合は内側から適用する。`1 < 2 == true` は `(1 < 2) == true` と解釈する。`1 < 2 < 3` と `1 == 1 != false` は同じ階層に演算子が二つあるため構文エラーとなる。

## 名前解決と型検査

トップレベルと各ブロックにスコープを置く。スコープ内の宣言と文をソース順にたどり、変数の読み取りと代入先を宣言IDに結び付ける。現在のスコープから外側へ探し、その位置より前にある最も近い宣言を選ぶ。

宣言を処理するときは、同じスコープの再宣言を先に調べる。次に宣言名を初期化中として登録し、初期値の式の名前解決を終えた時点で参照できるようにする。初期値の式から宣言自身の名前が参照されたら自己参照エラーとする。外側に同名の宣言があっても、その名前には結び付けない。内側の宣言より前の参照は外側の同名の宣言に結び付く。

名前解決をプログラム全体で終えてから、型を検査する。どちらの段階もスコープ内の文をソース順に、分岐を条件、`if` 側、`else` 側の順に、反復を条件、本体の順に調べる。実行されないブロックも調べる。代入の名前解決は代入先、右辺の順とし、二項式は左辺、右辺の順とする。型検査は式の子を左から調べ、その後に演算子や文が求める型を確認する。条件式の型はブロック内の文より先に確認する。

| 対象 | 必要な型 | 結果 |
| --- | --- | --- |
| 整数リテラル / `true`・`false` | | それぞれ `int` / `bool` |
| 変数参照 | 宣言済みの変数 | 宣言された型 |
| 単項 `-` / `!` | それぞれ `int` / `bool` | オペランドと同じ型 |
| `+`、`-`、`*`、`/`、`%` | 両辺が `int` | `int` |
| `<`、`<=`、`>`、`>=` | 両辺が `int` | `bool` |
| `==`、`!=` | 両辺が同じ型 | `bool` |
| 宣言の初期値・代入の右辺 | 宣言の注釈と一致 | 変数に値を格納 |
| `if`・`while` の条件 | `bool` | 実行するブロックを選択 |
| `print` の式 | `int` または `bool` | 値を1行出力 |

型は暗黙に変換しない。処理系は値の型タグを使って `bool` と `int` を区別する。

## 実行規則

文と宣言はソース順に実行する。二項演算は左辺、右辺、演算の順に評価する。途中で失敗した場合はそこで停止する。整数除算 `a / b` は商を負の無限大に向かって丸める。`b != 0` のとき `a = (a / b) * b + (a % b)` が成り立ち、ゼロ以外の剰余の符号は除数と同じになる。たとえば `-7 / 3` は `-3`、`-7 % 3` は `2` となる。`/` と `%` の除数がゼロなら実行時エラーとする。

宣言と代入は式の評価に成功してから値を格納する。ブロック内の宣言はブロックに入り直した場合も実行のたびに初期値を格納する。内側の宣言はブロックの外から参照できない。外側の変数に対する代入はブロックを出た後にも残る。

`if` は条件を1回評価し、真なら `if` 側、偽なら `else` 側を実行する。`else` がなければ偽のときは次の文へ進む。`while` は本体の前に毎回条件を評価し、真の間だけ本体を実行する。

`print` は式の評価に成功してから `int` を10進表記、`bool` を `true` または `false` として標準出力に書く。各行をLFで終える。出力する文は `print` に限る。

## 資源上限

上限値までは許容し、それを超える入力または処理を `E_LIMIT` で止める。

| 対象 | 上限 | 検査と診断位置 |
| --- | ---: | --- |
| ソース | 65,536バイト | UTF-8をデコードする前に計測する。位置なし |
| トークン | 8,192個 | EOFを除く。超過したトークン全体 |
| 構文の深さ | 64 | 構文解析中。下記の数え方と位置に従う |
| 整数1値の絶対値 | 4,096ビット | リテラルは字句解析時にリテラル全体、演算結果は演算直後に演算子の位置 |
| 出力 | 1,024行 | 式の評価後、出力前に検査する。超過した `print` のキーワード |
| 実行ステップ | 100,000回 | 次のステップの開始前に検査する。実行しようとした処理の位置 |

深さの上限は入れ子と構文木の両方に適用する。プログラム直下を深さ0とし、ブロックの `{`、式のグループ化の `(`、単項演算子ごとに、内側の解析中だけ入れ子の深さを1増やす。`if` と `while` の条件を囲む必須の括弧は数えない。入れ子の超過は深さ65に入るトークンで報告する。構文木の深さは文・宣言・ブロック・式をノードとし、葉を1、子のあるノードを子の最大深さに1を足した値とする。プログラム全体を表すルートとグループ化の括弧は数えない。ノード完成時に検査し、超過したノードの識別子、リテラル、演算子、文の先頭トークンのうち、該当するトークンを示す。二項式の連鎖は各二項ノードの完成時に検査する。

整数は `abs(value).bit_length()` 相当で数える。0は0ビットとする。リテラルは先頭のゼロを除いた値で検査する。未実行の分岐も含めて字句解析時に検査し、演算結果の範囲はその演算を実行したときに検査する。リテラルの読み取りと整数の10進出力には、本仕様の上限を適用する。

AST評価器は宣言、文、式のノードに入るたびに1ステップを数える。ブロックは入るたびに1ステップとし、文として現れるブロックも1回だけ数える。`while` 文への進入は1回とし、条件式の評価とブロックへの進入は反復ごとに数える。式のグループ化は括弧内の式だけを数える。ステップの位置は構文木深さの診断と同じトークンを使う。VMは停止命令を含む命令ごとに数え、命令に付けたソース位置を使う。実行ステップ上限に達するまでの出力と診断位置は処理系ごとに異なることがある。

## 診断

入力読み取り・サイズ検査、UTF-8デコード、字句解析、構文解析、名前解決、型検査、実行の順に処理する。VMでは型検査後にコンパイルと命令列の検査を行う。最初に失敗した段階の最初の1件を報告し、後続の段階へ進まない。字句解析は左から進め、各トークンについてトークン数、整数リテラルの範囲の順に確認する。構文解析時は期待した構文に合わない最初のトークンを報告する。比較や等値の連鎖は余分な演算子がそのトークンとなる。

診断を標準エラー出力に書く。診断には `code`、`phase`、`message`、`line`、`column`、`span` を持たせる。文言 `message` は人向けで、比較の対象はコード、段階、位置とする。

元のバイト列における `span` は0始まりで、開始を含み終了を含まない。行・列は1始まりとし、列は行頭から数えたUnicodeコードポイントの位置とする。タブは1文字とする。CRLFは1改行、2バイトとして数える。EOFで記号が不足した場合はEOFの位置で長さ0の範囲を示す。入力の不正なUTF-8は最初の不正なシーケンスの先頭1バイトを示し、行・列はその直前までの正常なUTF-8から数える。位置のない診断は `line`、`column`、`span` をいずれも `null` とする。

| コード | 段階 `phase` | 条件と位置 | 終了コード |
| --- | --- | --- | ---: |
| `E_INPUT` | `input` | 読み取りに失敗した場合は位置なし。不正UTF-8は上記の位置 | 2 |
| `E_LEX` | `lex` | 不正な文字1コードポイント | 2 |
| `E_PARSE` | `parse` | 構文に合わないトークンまたはEOF | 2 |
| `E_UNDEFINED` | `resolve` | 宣言が見つからない読み取りまたは代入先の識別子 | 2 |
| `E_SELF_REFERENCE` | `resolve` | 初期値内にある宣言自身の参照箇所 | 2 |
| `E_REDECLARATION` | `resolve` | 同じスコープで後から宣言された識別子 | 2 |
| `E_TYPE` | `type` | 演算子の型違反は演算子。初期値・代入の型不一致は変数名。条件の型違反は `if` または `while` | 2 |
| `E_ZERO_DIVISION` | `runtime` | 除数が0の `/` または `%` | 3 |
| `E_LIMIT` | `input`、`lex`、`parse`、`runtime` | 資源上限の表に従う | 実行時は3、それ以前は2 |
| `E_INTERNAL` | `internal` | 処理系の不具合。原因となるソース位置を特定できれば示す | 4 |

成功時は終了コード0とする。入力・字句・構文・名前・型のエラー時はプログラムの標準出力を空にする。実行時エラーではそれまでに成功した `print` の出力を残す。

## 処理系の構成

```text
ソース → scanner → トークン → parser → AST → resolver → type checker
                                                               ├→ interpreter ──────────────→ 出力
                                                               └→ compiler → 命令列 → VM → 出力
```

`tiny_language/` に各処理を配置する。VMはスタック方式とし、変数を宣言IDに対応するスロットへ配置する。各命令にソース位置とスタック効果を定義し、命令の妥当性、ジャンプ先の範囲、スタック不足、分岐合流時のスタック深さの一致を検査する。命令列はメモリ内で生成して実行する。外部バイトコードの読み込みは対象外とする。利用者のソースをホストの `eval`・`exec` に渡して実行してはならない。

CLIは `261126/` から `python3 -m tiny_language` で起動する。Phase 1の `--tokens PATH` は字句解析まで、`--ast PATH` は構文解析までを行い、成功時に中間結果を表示する。Phase 2では `run --engine ast PATH`、Phase 3では `run --engine vm PATH` と逆アセンブル・トレースを追加する。診断の位置はトークンからASTと命令列へ引き継ぐ。
