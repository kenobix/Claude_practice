# ハブのバックアップと復元

LinuxまたはWSL2のLinuxファイルシステムで、CLIで作成した1同期領域・2端末のハブを対象にする。元ハブ、バックアップ、復元先は同じ信頼済みボリュームに置く。各コマンドはボリュームからの相対パスで対象を指定する。保存先の親は先に用意し、保存先の名前は未使用にする。既存のファイル、ディレクトリ、リンクは上書きしない。元と先の入れ子も拒否する。

## バックアップの取得

1. ハブを停止する。停止が完了していない場合は、保存先の準備前にハブの排他ロック取得が失敗する。
2. ハブの論理長と、保存先の空きディスク容量を確認する。バックアップは別のコピーになるため、ハブの2 GiB枠とは別に空きが必要になる。前回の中断で残った準備ディレクトリも確認する。
3. 次のコマンドを実行する。例では `demo` はボリュームの絶対パス、`bin` はビルド済みCLIの絶対パスで、保存先 `backup-1` は未作成とする。

   ```bash
   "$bin" hub-backup -volume "$demo" -source hub -destination backup-1
   ```

ハブの排他を保持して通常の起動時照合を行い、WALを `TRUNCATE` チェックポイントで空にして単一接続を閉じる。そこからDB本体と登録済みの全blobをコピーする。現行版から参照されていない旧版や未参照のblobも対象。コピー先のDBで整合性と外部キーを確認し、`backup.json` の形式版、世代、DBとblobの長さ・SHA-256を実体・登録一覧と照合する。ファイルと親を同期し、保存先名へ排他的にrenameした後に成功を返す。 [SQLiteのWAL](https://sqlite.org/wal.html)・[チェックポイント](https://sqlite.org/pragma.html#pragma_wal_checkpoint)

バックアップにはファイル本文、履歴、端末ID、トークンのダイジェストを含む。バックアップの持ち出しや保管では元ハブと同じアクセス制限を保つ。トークンの平文と端末の送信待ち・作業フォルダはバックアップに含まれない。

## 別保存先への復元

1. 復元元を編集せず、利用中のハブと端末を停止した状態で切替を行う。旧ハブ、バックアップ、端末のルートと管理領域は保管する。
2. 元の領域ID・2端末のIDと、現在使うトークンを用意する。旧トークンを失効させる場合は新しい値を指定し、その値を各端末にも別途設定する。端末IDや領域IDがバックアップと異なると復元は拒否される。
3. 存在しない別名を指定して復元する。次の `space_id`、`client_a`、`client_b` は管理設定の値、`current_a` と `current_b` は用意したトークンとする。

   ```bash
   FILE_SYNC_TOKEN_A="$current_a" FILE_SYNC_TOKEN_B="$current_b" \
     "$bin" hub-restore -volume "$demo" -source backup-1 -destination hub-restored \
       -space "$space_id" -client-a "$client_a" -client-b "$client_b"
   ```

4. 成功時に表示される `hub_generation` がバックアップの世代と異なることを確かめてから、復元先を指定してハブを起動する。クライアントは旧世代の通常同期を停止する。新しい世代のmanifestと手元の内容、旧送信待ちを確認し、端末ごとに明示的に再登録する。 [再登録の操作手順](conflicts.md#状態消失や世代変更の後に再登録する)

   ```bash
   "$bin" hub -volume "$demo" -root hub-restored -listen 127.0.0.1:8080
   ```

復元ではDBとblobをコピーして再照合し、新しい世代と現在の認証ダイジェストを同じSQLiteトランザクションで確定する。旧世代の受理履歴は残る。復元後に旧世代の要求が届くと、操作IDが受理済みでも、CASの期待版が一致していても、`409 generation_mismatch` となる。同世代の通常再起動では世代IDを維持する。DB本体だけを手作業で過去の版に差し替える運用は、正式な復元手順の保証範囲外となる。

## 中断時の確認

正式名に切り替える前に停止すると、その名前は未作成のまま、隣接する `.file-sync-offline-<ID>` に途中のコピーが残る。復元の世代確定と検査が終わるまでは、途中の復元先からハブを起動できない。停止位置に迷う場合は、元の指定先と準備ディレクトリの両方を確認し、新しい保存先名で再実行する。正式名の公開直後に応答が途絶えた場合は、既存先が拒否される。復元では元バックアップと旧ハブ、端末の作業を保持したまま、完成した保存先を照合する。自動再開や準備領域の自動削除は行わない。 [停止点と判定](phase4-verification.md)
