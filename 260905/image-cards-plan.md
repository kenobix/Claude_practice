# フラッシュカードへの画像添付 方針ドキュメント

テキストだけのカードは「構造・段階・階層・比較」を扱う内容（正規化の段階、ER図、トランザクション分離レベルの階層、原価計算の流れなど）だと関係性が頭に入りにくい、という課題への対応方針。GPT-4o(ChatGPT)やGemini(Nano Banana/Imagen)などの画像生成AIで解説図を作り、カードの裏面に添付する。

このドキュメントは**方針とプロンプトのみ**を定めるもので、アプリ本体のコード実装はまだ行っていない（末尾の「実装チェックリスト」を参照）。

## 基本方針

1. **画像は装飾ではなく、情報を追加する場合だけ使う**。すでにテキストの一問一答で十分な内容（用語の定義、単純な数値など）には画像をつけない。
2. **画像をつける価値が高いのは「構造・手順・比較・階層」を扱うカード**。例:
   - 正規化の段階(UNF→1NF→2NF→3NF→BCNF)
   - ER図・テーブル間のリレーション
   - トランザクション分離レベルの強さの順序
   - インデックス(B+木)の構造
   - 工業簿記の原価計算の流れ(費目別→部門別→製品別)
3. **1枚の図を、その概念クラスタに属する複数カードで共有する**。カードごとに新規画像は作らない。
   - 例: 正規化5段階の図を1枚作れば、「第1正規形の条件は？」「BCNFの条件は？」など単元内の複数カードから同じ画像を参照できる
4. **画像はカードの裏面(答え側)にだけ表示する**。表面は今まで通りテキストのみとし、「考えてから答えを見る」フローを妨げない。
5. 既存の配色・トーン（暖色寄りのAI生成っぽい配色を避けた紙面グレー＋琥珀色1色のアクセント）に画像のトーンを合わせ、アプリ全体の統一感を保つ。

## データ構造の変更案

各カードに省略可能な `image` フィールド(ファイル名)と `imageAlt` フィールド(代替テキスト)を追加する。

```json
{
  "front": "第1正規形(1NF)の条件は？",
  "back": "すべての属性値が原子値であること。繰り返し項目を持たない。",
  "image": "normalization-forms.png",
  "imageAlt": "未正規化から第1〜3正規形・ボイスコッド正規形までの5段階を、各段階のテーブル例つきで示した図"
}
```

同じ `image` ファイル名を複数カードで指定すれば、それだけで画像が共有される（マッピングファイルなどは不要）。

画像本体は、セットごとに以下の場所へ置く。

```
sets/<set-id>/images/normalization-forms.png
sets/<set-id>/images/isolation-levels.png
```

## 命名・管理のガイドライン

- ファイル名は英語・ケバブケースで内容が分かる名前にする(例: `normalization-forms.png`, `isolation-levels.png`)
- 1つの単元(unit)につき、大きな図解が必要な概念は多くても2〜3枚程度に抑える(作りすぎ防止)
- 画像を追加したら、その単元のどのカードがどの画像を共有しているかを一覧化しておくと、後から似た図を重複生成するのを防げる(下記の「管理表」参照)
- ファイルサイズはGitHub Pagesがそのまま配信する(サーバー側での最適化なし)ため、**1枚あたり300〜500KB程度、横幅1200px前後**を目安に生成AI出力後に手元でリサイズ・圧縮する

### 管理表の例(単元ファイルとは別に、セットごとに1つ置くと便利)

| 画像ファイル | 使用しているカード(front) | 内容 |
|---|---|---|
| `normalization-forms.png` | 第1正規形の条件は？ / 第2正規形の条件は？ / 第3正規形の条件は？ / BCNFの条件は？ | UNF→1NF→2NF→3NF→BCNFの5段階を1枚で図解 |

## デザイン・スタイルの統一方針

- 背景は薄いオフホワイト〜ペーパーグレー。アクセントカラーは琥珀色(`#C6862B`前後)1色のみ使い、それ以外は黒に近い濃いグレーの文字・線でまとめる
- 派手なグラデーション、ネオンカラー、絵文字調の3Dアイコンは使わない。教科書の図解のような落ち着いたトーンにする
- 文字はすべて日本語、読みやすいゴシック体
- 縦横比は16:9前後の横長(フラッシュカードの裏面が横長レイアウトのため)

## 生成AIへの依頼プロンプト例

ChatGPT(GPT-4o画像生成)・Gemini(Nano Banana/Imagen)のどちらでも使える汎用テンプレート。`{{ }}` の部分を差し替えて使う。

```
以下の条件で、学習用の解説図(インフォグラフィック)を1枚生成してください。

# 内容
テーマ: {{例: データベースの正規化(第1正規形からボイスコッド正規形まで)}}

このテーマを、次の段階/要素に分けて図解してください:
{{各段階の名称と簡単な説明を箇条書きで入れる。例:
1. 未正規化(UNF) - 繰り返しグループを含むデータ
2. 第1正規形(1NF) - すべての属性値が原子値
3. 第2正規形(2NF) - 部分関数従属の排除
4. 第3正規形(3NF) - 推移的関数従属の排除
5. ボイスコッド正規形(BCNF) - すべての決定子が候補キー}}

各段階には「見出し」「1〜2行の説明」「該当する場合は具体例(小さな表)」を
含めてください。段階どうしのつながりが分かるよう、矢印または番号で順序を
示してください。

# デザインの指定
- 教科書の図解のように落ち着いたトーンにすること。派手なグラデーション、
  ネオンカラー、絵文字風の3Dアイコンは使わないこと
- 背景は薄いオフホワイト〜ペーパーグレー。アクセントカラーは琥珀色
  (マスタード寄りのオレンジ、#C6862B前後)を1色だけ使い、それ以外は
  黒に近い濃いグレーの文字・線でまとめること
- 文字はすべて日本語で、読みやすいゴシック体にすること
- 縦横比は16:9程度の横長にすること
- タイトルを図の最上部に大きく、1行程度のサブタイトルをその下に置くこと
- 各段階を横に並べたカード/パネル状のレイアウトにし、間を矢印でつなぐこと
- 図の下部に、この図全体の要点をまとめた1行の補足を入れること
```

複数カードで共有する図(例: 分離レベルの階層、原価計算の流れ)を作る場合も同じテンプレートで、「段階」を「比較対象」や「工程」に読み替えれば流用できる。

生成後は、そのまま添付せず一度目を通して**内容が正確か確認**すること(生成AIの図解は文字の綴りや矢印の向きを間違えることがある)。

## 実装チェックリスト(未着手・今後の作業)

このドキュメントは方針とプロンプトの整理までで、アプリ本体には未反映。実装する場合は以下が必要になる。

1. `sets/<id>/images/` ディレクトリを作り、生成した画像を配置
2. 各単元JSONのカードに `image` / `imageAlt` フィールドを追加
3. `js/store.js` の `makeCard()` が `image` / `imageAlt` を素通しするよう拡張(現状は既知のフィールドしか保持しないため、追加しないと画像参照が消える)
4. `js/review.js` の `renderReviewCurrent()` で、`card.image` があればカード裏面に `<img>` を表示するよう変更。パスは `sets/<card.setId>/images/<card.image>` を組み立てる
5. `css/review.css` に画像用のスタイル(最大幅100%・角丸・余白)を追加。画像読み込み失敗時はテキストのみにフォールバックする(`onerror`で非表示)
6. 任意: カード一覧(`js/deck.js`)に「図あり」バッジを表示し、どのカードに画像がついているか一目でわかるようにする
