# 忘却曲線フラッシュカードアプリ

エビングハウスの忘却曲線を使った間隔反復（Spaced Repetition）学習アプリ。GitHub Pagesで動作する静的サイト（外部API・ビルド不要）。

**公開URL:** https://kenobix.github.io/Claude_practice/260905/

## 何を作ったか

- カードの表面（問い）・裏面（答え）を登録し、復習セッションで自己評価しながら覚える単純なフラッシュカードアプリ
- カードは手入力だけでなく、「データベーススペシャリスト試験」「簿記2級」のようにトピックごとのセット（`sets/`）から一括で読み込める
- ダッシュボードのヒーロー要素として、登録カードそれぞれの忘却曲線（薄い線）と全体の平均忘却曲線（太いアクセント線）を1枚のSVGチャートに重ねて表示。「今」を境に、過去の実績と将来の予測がひと続きの曲線として見える
- 復習のたびに「もう一度 / 難しい / 普通 / 簡単」の4段階で自己評価し、評価に応じて次の復習日を自動計算
- すべて `localStorage` に保存。サーバー・APIキーなし

```

    components.css   … ダッシュボード(チャート・復習待ちパネル・表ビュー)
    review.css         … 復習セッション(フラッシュカード・採点ボタン)
    deck.css            … カード一覧・追加フォーム・セット読み込みUI
  js/
    config.js          … 定数・配色トークンの読み出し

    srs.js                … 忘却曲線の計算式・間隔反復ロジック(純粋関数)
    cardSets.js        … sets/ からカードセットを読み込む
    store.js            … localStorageへの永続化・カードCRUD
    chart.js             … 忘却曲線チャートの自作SVG描画
    dashboard.js      … ダッシュボード画面

    deck.js               … カード一覧・追加・セット読み込み画面

  sets/
    manifest.json                … 読み込むセットのファイル名一覧
    database-specialist.json  … データベーススペシャリスト試験セット(10枚)
    bookkeeping-2kyu.json       … 簿記2級セット(10枚)
```

`sets/`はリポジトリ全体の`.gitignore`にある`**/data/`パターンを避けるため、あえて`data/sets/`ではなく`sets/`という名前にしている。

`js/`配下はネイティブのES Modules(`<script type="module">`)で読み込んでおり、バンドラー等のビルドステップは無い。そのため`index.html`をブラウザで直接開く(`file://`)と`type="module"`のスクリプトも`fetch`によるセット読み込みもブロックされる。**必ずローカルサーバー経由で開くこと**（後述の確認方法を参照）。GitHub Pagesは通常のHTTP配信なので問題なく動作する。

## 忘却曲線と間隔反復のロジック

保持率 `R` を、経過日数 `t`・カードごとの「安定度」`S`（日）を使って次の式で近似している（`js/srs.js`）。

```
R(t) = 0.9 ^ (t / S)
```

`S` は「保持率が90%まで落ちるのにかかる日数」として定義しており、`t = S` の時点で必ず `R = 0.9` になる。エビングハウスの指数関数的な減衰の形をそのまま使いつつ、`S` を直接「次の復習までの間隔（日数）」として扱えるようにした簡易版（Ankiの2.0以前のアルゴリズムに近い考え方）。

復習時の自己評価によって `S` を更新する（簡易SM-2方式）。

| 評価 | 新しい安定度 |
|---|---|
| もう一度 | `S × 0.3`（最低1日） |
| 難しい | `S × 1.2` |
| 普通 | `S × 2.5` |
| 簡単 | `S × 3.5` |

新規カードの初期安定度は1日。次回復習日は `最終復習日時 + 新しい安定度(日)` で算出する。「もう一度」を選んだカードは、その場の復習セッション内でも数枚後にもう一度出題される。

より精密なFSRS（Free Spaced Repetition Scheduler）のような、実際の保持率や難易度パラメータまで加味したアルゴリズムではないが、「忘却曲線を可視化しながら間隔反復で学ぶ」という体験を成立させるには十分な近似として採用した。

## カードセットの追加方法

`sets/` に新しいJSONファイルを1つ置き、`manifest.json` にそのファイル名を追記するだけで、アプリの「カード一覧」画面の「セットから追加」に新しいセットが表示されるようになる。

1. 下記の「生成AIへの依頼プロンプト例」を使って、学びたいトピックのカードをJSON配列で生成してもらう
2. 出力されたJSON配列を `cards` に入れ、`id`（英数字とハイフンのみ）と `name`（画面に表示される名前）を付けて、次の形式で `sets/<id>.json` として保存する

```json
{
  "id": "your-set-id",
  "name": "表示名(例: 応用情報技術者試験 午前)",
  "cards": [
    { "front": "問い", "back": "答え" }
  ]
}
```

3. `sets/manifest.json` の配列に `"your-set-id.json"` を追記する

```json
["database-specialist.json", "bookkeeping-2kyu.json", "your-set-id.json"]
```

セットの読み込みは`front`の文字列で重複チェックしているため、同じセットを複数回「追加」しても二重登録はされない。

### 生成AIへの依頼プロンプト例

このアプリの `cards` 配列の形式（`{"front": "問い", "back": "答え"}` のJSON配列）にそのまま合うように、Claude・ChatGPT等の生成AIに次のようなプロンプトで依頼すると、貼り付けるだけで使えるデータが得られる。

```
あなたは暗記用フラッシュカードの作成者です。以下の条件で、学習トピック
「{{ここに学習したい試験・分野名を入れる。例: 応用情報技術者試験 午前}}」
のフラッシュカードを{{枚数。例: 20}}枚作成してください。

# 出力形式
- 出力はJSON配列のみ。前後に説明文やコードブロックの言語表記以外の文章を
  含めないこと
- 各要素は次の形式のオブジェクトにすること
  { "front": "問い(質問文)", "back": "答え(簡潔な解説文)" }
- frontは1文の質問形式にすること(語句の意味を問う、比較を問う、計算式を
  問う、など)
- backは1〜2文程度で簡潔に。丸暗記しやすいよう、余計な前置きをつけない
  こと
- 同じ内容を言い換えただけの重複カードを作らないこと
- 難易度は{{初級/中級/上級など}}を想定すること

# 出力例
[
  { "front": "TCPとUDPの違いは？", "back": "TCPは接続指向・信頼性重視、UDPは非接続・低遅延重視。" },
  { "front": "第3正規形(3NF)の条件は？", "back": "第2正規形を満たし、かつ非キー属性間に推移的関数従属が存在しないこと。" }
]
```

出力されたJSON配列を丸ごと `cards` の値として使えば、`sets/<id>.json` が完成する。生成AIの出力は誤りを含むことがあるため、特に資格試験など正確性が重要な内容は、登録前に自分でも一度目を通して確認することを推奨する。

## 設計上の判断

- **UIデザイン**: `anthropics/skills@frontend-design`（GitHub上のAgent Skills、855.9K install・Anthropic公式）をプロジェクトスコープで導入し、その原則に沿って設計した。
  - クリーム背景+テラコッタ配色や黒背景+ネオン配色など「AI生成っぽい」定番配色を避け、「紙の上のインク」という主題（記憶の強弱＝インクの濃淡）に根ざした配色にした（寒色寄りのペーパーグレー `#EEF0EA` + 琥珀色のアクセント `#C6862B` 1色のみ）
  - ダッシュボードのヒーローは「大きい数字+グラデーション」の定番ではなく、忘却曲線グラフそのものにした
  - カード一覧のカード文字色は、そのカードの現在の保持率に応じてインクの濃さ（強い記憶=濃いインク・弱い記憶=薄いインク）で表現。これは装飾ではなく情報を担う視覚要素として設計した
  - モーションはカード反転の1箇所と、ダッシュボード表示時の平均曲線の描画アニメーションのみに絞り、`prefers-reduced-motion` を尊重する
- **チャートの設計**: dataviz観点のガイドライン（1系列を強調し他を控えめにする「emphasis」パターン、ホバー時のクロスヘア+ツールチップ、表ビューという代替手段の提供、軸ラベルは`tabular-nums`、系列の色を文字に使わない等）に沿って自作SVGで実装。外部チャートライブラリは使っていない
- **ファイル分割**: 画面(ダッシュボード/復習/カード一覧)・データ層(store/srs/cardSets)・描画(chart)・共通処理(utils/config)で責務ごとにモジュールを分け、ES Modulesの`import`/`export`で繋いでいる。バンドラーなしでも保守しやすい単位に分割することを優先した
- **カードデータの分離**: カードの内容(`sets/*.json`)とアプリのロジック・見た目(`js/`・`css/`)を完全に分離した。セットの追加・編集にJavaScriptの知識は不要
- 初回アクセス時は最初のカードセット(データベーススペシャリスト試験)から数枚をデモとして自動で取り込む（`localStorage`が空の場合のみ）。カードの内容自体は実データだが、「数日前に復習した」という履歴だけはダッシュボードの曲線をすぐ意味あるものにするための演出。いつでも削除・編集できる

## 確認方法

```
cd 260905
python3 -m http.server 8905
# ブラウザで http://localhost:8905/ を開く
```

- カード追加→一覧に反映されること、次回復習日・保持率が表示されること
- 「カード一覧」画面で「セットから追加」→任意のセットを選んで追加すると、そのセットのカードが一覧に増えること。もう一度追加すると重複がスキップされること
- 復習セッションでカードをクリック/Enter/Spaceキーで反転し、4段階評価で次のカードに進むこと。「もう一度」を選んだカードが同じセッション内で再度出題されること
- ダッシュボードのグラフがカードの状態を反映し、ホバーでクロスヘア＋ツールチップが出ること。「表で見る」から表ビューに切り替えられること
- ページをリロードしても`localStorage`からカード・復習履歴が復元されること
- モバイル幅（375px程度）でもレイアウトが崩れないこと
