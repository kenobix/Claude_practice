# 忘却曲線フラッシュカードアプリ

エビングハウスの忘却曲線を使った間隔反復（Spaced Repetition）学習アプリ。GitHub Pagesで動作する静的サイト（外部API・ビルド不要）。

**公開URL:** https://kenobix.github.io/Claude_practice/260905/

## 何を作ったか

- カードの表面（問い）・裏面（答え）を登録し、復習セッションで自己評価しながら覚える単純なフラッシュカードアプリ
- 「データベーススペシャリスト試験」「簿記2級」の2セット（各50〜70枚、単元ごとに分類）を最初から同梱。ヘッダーの「学習セット」でダッシュボード・復習・カード一覧のすべてを特定のセット（または自分で追加したカードだけ）に絞り込める
- ダッシュボードのヒーロー要素として、選択中のカードそれぞれの忘却曲線（薄い線）と全体の平均忘却曲線（太いアクセント線）を1枚のSVGチャートに重ねて表示。「今」を境に、過去の実績と将来の予測がひと続きの曲線として見える
- 復習のたびに「もう一度 / 難しい / 普通 / 簡単」の4段階で自己評価し、評価に応じて次の復習日を自動計算。復習画面はクリックの他に**キーボード操作**（Space/Enterで裏返す、1〜4キーで評価）にも対応し、直前の評価は「元に戻す」で取り消せる
- カード裏面には図解画像を添付できる（`image`/`imageAlt`フィールド、複数カードで1枚の図を共有）。同梱2セット・計141枚のうち111枚に、生成AI(Gemini)で作成した図解32枚を割り当て済み（`sets/<id>/images/`。方針とプロンプト全文は [image-cards-plan.md](image-cards-plan.md)）
- すべて `localStorage` に保存。サーバー・APIキーなし

## 忘却曲線と間隔反復のロジック

保持率 `R` を、経過日数 `t`・カードごとの「安定度」`S`（日）を使って次の式で近似している（`js/srs.js`）。

```
R(t) = 0.9 ^ (t / S)
```

`S` は「保持率が90%まで落ちるのにかかる日数」として定義しており、`t = S` の時点で必ず `R = 0.9` になる。エビングハウスの指数関数的な減衰の形をそのまま使いつつ、`S` を直接「次の復習までの間隔（日数）」として扱えるようにした簡易版（Ankiの2.0以前のアルゴリズムに近い考え方）。

復習時の自己評価によって `S` を更新する（簡易SM-2方式）。

| 評価 | 新しい安定度 |
|---|---|
| もう一度 | `S × 0.3`（最低1日） |
| 難しい | `S × 1.2` |
| 普通 | `S × 2.5` |
| 簡単 | `S × 3.5` |

新規カードの初期安定度は1日。次回復習日は `最終復習日時 + 新しい安定度(日)` で算出する。「もう一度」を選んだカードは、その場の復習セッション内でも数枚後にもう一度出題される。評価は直後であれば「元に戻す」で取り消せる（カードの安定度・復習履歴・セッションの出題順を評価前の状態に復元する）。

より精密なFSRS（Free Spaced Repetition Scheduler）のような、実際の保持率や難易度パラメータまで加味したアルゴリズムではないが、「忘却曲線を可視化しながら間隔反復で学ぶ」という体験を成立させるには十分な近似として採用した。

## データセットの切り替え

ヘッダーの「学習セット」セレクトで、ダッシュボードのグラフ・復習の出題対象・カード一覧の表示を、選んだデータセットだけに絞り込める。選択肢は「すべてのカード」「データベーススペシャリスト試験」「簿記2級」「自分で追加したカード」。

初回アクセス時は、読み込めた全セットの全カードが最初から取り込まれた状態になる（各セットの数枚だけ「数日前に復習した」という履歴付きで、残りは復習待ちの新規カードとして）。そのため`sets/`に新しいセットを追加すれば、次にブラウザの`localStorage`を初期化した人には自動的にそのセットも含まれる。既存ユーザーの手元には自動反映されないため、後から追加した内容を取り込みたい場合は「カード一覧」の「セットから追加」を使う（front文字列で重複判定するため、二重登録はされない）。

## カードセットの追加方法

`sets/` に新しいディレクトリを1つ作り、`manifest.json` にそのディレクトリ名を追記するだけで、アプリの「学習セット」「セットから追加」に新しいセットが表示されるようになる。カードが増えてもJSON1ファイルが肥大化しないよう、セットは「単元(unit)」ごとに複数ファイルへ分割する構成にしている。

1. 下記の「生成AIへの依頼プロンプト例」を使って、学びたいトピックを単元に分けてもらい、各単元のカードをJSON配列で生成してもらう
2. `sets/<id>/` ディレクトリを作り、単元ごとに次の形式でファイルを保存する

```json
{
  "unit": "単元の表示名(例: 第2章 需要と供給)",
  "cards": [
    { "front": "問い", "back": "答え" }
  ]
}
```

3. 同じディレクトリに `meta.json` を置き、`id`（英数字とハイフンのみ）・`name`（画面に表示されるセット名）・`units`（単元ファイル名を学習順に並べた配列）を書く

```json
{
  "id": "your-set-id",
  "name": "表示名(例: 応用情報技術者試験 午前)",
  "units": ["unit1.json", "unit2.json"]
}
```

4. `sets/manifest.json` の配列に `"your-set-id"` を追記する

```json
["database-specialist", "bookkeeping-2kyu", "your-set-id"]
```

単元ファイルの数・粒度に決まりはない。1ファイルあたり10〜15枚程度に収まるよう分けると読みやすい。セットの読み込みは`front`の文字列で重複チェックしているため、同じセットを複数回「追加」しても二重登録はされない。

### 生成AIへの依頼プロンプト例

このアプリの単元ファイルの形式（`{"front": "問い", "back": "答え"}` のJSON配列）にそのまま合うように、Claude・ChatGPT等の生成AIに次のようなプロンプトで依頼すると、貼り付けるだけで使えるデータが得られる。単元分けもまとめて依頼する形にしてある。

```
あなたは暗記用フラッシュカードの作成者です。学習トピック
「{{ここに学習したい試験・分野名を入れる。例: 応用情報技術者試験 午前}}」
について、まず5〜6個の単元(章立て)に分け、単元ごとに8〜14枚程度の
フラッシュカードを作成してください（合計50〜70枚程度）。

# 出力形式
- 出力はJSON配列のみ。前後に説明文やコードブロックの言語表記以外の文章を
  含めないこと
- 各要素は次の形式のオブジェクトにすること
  { "unit": "単元名(日本語)", "front": "問い(質問文)", "back": "答え(簡潔な解説文)" }
- frontは1文の質問形式にすること(語句の意味を問う、比較を問う、計算式を
  問う、など)
- backは1〜2文程度で簡潔に。丸暗記しやすいよう、余計な前置きをつけない
  こと
- 同じ内容を言い換えただけの重複カードを作らないこと
- 難易度は{{初級/中級/上級など}}を想定すること
- 自信の持てない細かい数値・固有名詞は無理に含めず、確実な内容に絞ること

# 出力例
[
  { "unit": "ネットワーク基礎", "front": "TCPとUDPの違いは？", "back": "TCPは接続指向・信頼性重視、UDPは非接続・低遅延重視。" },
  { "unit": "データベース設計", "front": "第3正規形(3NF)の条件は？", "back": "第2正規形を満たし、かつ非キー属性間に推移的関数従属が存在しないこと。" }
]
```

出力されたJSON配列を`unit`ごとにグループ分けし、上記「カードセットの追加方法」の形式（単元ファイル+meta.json）に整形すれば完成する。生成AIの出力は誤りを含むことがあるため、特に資格試験など正確性が重要な内容は、登録前に自分でも一度目を通して確認することを推奨する。

同梱の2セット（データベーススペシャリスト試験・簿記2級、計141枚）もこの方法で、Claude Codeのサブエージェントに公式シラバス・検定試験サイトなどをWeb検索させて作成した。

## 設計上の判断

- **UIデザイン**: `anthropics/skills@frontend-design`（GitHub上のAgent Skills、855.9K install・Anthropic公式）をプロジェクトスコープで導入し、その原則に沿って設計した。
  - クリーム背景+テラコッタ配色や黒背景+ネオン配色など「AI生成っぽい」定番配色を避け、「紙の上のインク」という主題（記憶の強弱＝インクの濃淡）に根ざした配色にした（寒色寄りのペーパーグレー `#EEF0EA` + 琥珀色のアクセント `#C6862B` 1色のみ）
  - ダッシュボードのヒーローは「大きい数字+グラデーション」の定番ではなく、忘却曲線グラフそのものにした
  - カード一覧のカード文字色は、そのカードの現在の保持率に応じてインクの濃さ（強い記憶=濃いインク・弱い記憶=薄いインク）で表現。これは装飾ではなく情報を担う視覚要素として設計した
  - モーションはカード反転の1箇所と、ダッシュボード表示時の平均曲線の描画アニメーションのみに絞り、`prefers-reduced-motion` を尊重する
- **チャートの設計**: dataviz観点のガイドライン（1系列を強調し他を控えめにする「emphasis」パターン、ホバー時のクロスヘア+ツールチップ、表ビューという代替手段の提供、軸ラベルは`tabular-nums`、系列の色を文字に使わない等）に沿って自作SVGで実装。外部チャートライブラリは使っていない
- **ファイル分割**: 画面(ダッシュボード/復習/カード一覧)・データ層(store/srs/cardSets)・描画(chart)・共通処理(utils/config)で責務ごとにモジュールを分け、ES Modulesの`import`/`export`で繋いでいる。バンドラーなしでも保守しやすい単位に分割することを優先した
- **カードデータの分離**: カードの内容(`sets/**/*.json`)とアプリのロジック・見た目(`js/`・`css/`)を完全に分離し、さらにセットごと・単元ごとにファイルを分けた。セットの追加・編集にJavaScriptの知識は不要
- **既存の間隔反復アプリ(Anki等)との機能差の埋め合わせ**: 当初のバージョンにはなかったが優先度が高いと判断し追加した機能
  - キーボードだけで復習を完結できる操作(Space/Enterで裏返す、1〜4キーで評価)
  - 直前の評価を取り消す「元に戻す」
  - 複数の学習対象(デッキ)を切り替える機能(ヘッダーの「学習セット」)
- 初回アクセス時は、読み込めた全セットの全カードを取り込む（`localStorage`が空の場合のみ）。各セットの最初の数枚だけ「数日前に復習した」という履歴を持たせ、ダッシュボードの曲線が最初から意味を持つようにしている（内容自体は実データ）。いつでも削除・編集できる

## 確認方法

```
cd 260905
python3 -m http.server 8905
# ブラウザで http://localhost:8905/ を開く
```

- ヘッダーの「学習セット」で「データベーススペシャリスト試験」「簿記2級」「自分で追加したカード」に切り替えると、ダッシュボードのグラフ・復習待ち件数・カード一覧がそれぞれ絞り込まれること
- カード追加→一覧に反映されること、次回復習日・保持率が表示されること
- 「カード一覧」画面で「セットから追加」→任意のセットを選んで追加すると、そのセットのカードが一覧に増えること。もう一度追加すると重複がスキップされること
- 復習セッションでカードをクリック/Enter/Spaceキーで反転し、4段階評価（クリックまたは1〜4キー）で次のカードに進むこと。「もう一度」を選んだカードが同じセッション内で再度出題されること。「元に戻す」で直前の評価が取り消せること
- ダッシュボードのグラフがカードの状態を反映し、ホバーでクロスヘア＋ツールチップが出ること。「表で見る」から表ビューに切り替えられること
- ページをリロードしても`localStorage`からカード・復習履歴が復元されること
- モバイル幅（375px程度）でもレイアウトが崩れないこと
- 復習セッションでカードを裏返すと、`image`が設定されたカードは図解画像が表示され、`imageAlt`がalt属性に入っていること。画像ファイルが無いカードはエラーにならずテキストのみで表示されること（Playwrightで全32種の画像読み込みを確認済み、`js/utils.js`の`imagePathFor`が組み立てるパスは`sets/<setId>/images/<image>`）
